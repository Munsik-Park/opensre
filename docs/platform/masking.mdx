title: "Masking Sensitive Identifiers"
description: "Reversible masking of pod, cluster, and account identifiers before external LLM calls."
---

## Overview

OpenSRE can mask sensitive infrastructure identifiers (pod names, cluster names,
hostnames, account IDs, service names, IP addresses, emails) **before** sending
text to an external LLM, then restore the originals in what you see and what is
stored. Teams can use external models while keeping raw identifiers inside the
agent runtime.

Masking is **off by default**. Turn it on with environment variables — no code
changes required. Settings are read when a turn first masks a request, so a
change applies on the next turn without a restart. A `/goal` run reads them
once for all its turns: a change applies on the next run.

## What is masked

When masking is on, every request OpenSRE sends to an LLM provider carries
placeholders such as `<POD_0>`, `<NAMESPACE_0>` or `<CLUSTER_1>` instead of the
identifiers. This holds for CLI-backed providers (Copilot CLI, Claude Code,
Codex and the other CLI adapters) and for hosted API providers (Anthropic,
OpenAI and OpenAI-compatible providers, Bedrock, LiteLLM), for agent turns and
for the background requests: goal checks, memory, conversation summaries,
knowledge scans and the daily update.

Masked:

- your message and earlier turns of the conversation;
- tool results, and the tool arguments replayed in later requests;
- environment content in the system prompt: setup state, connected integrations,
  repository context, workspace knowledge and long-term memory.

Sent as written: OpenSRE's own instructions, the tool definitions, the built-in
system prompt and skill text.

A namespace, cluster or service name is detected after its label, written as
text (`namespace: payments`, `in namespace payments`) or as a structured field
(`"namespace": "payments"`).

## Where originals come back

- Tool arguments are restored before the tool runs, so queries, approvals and
  hooks use the real identifiers.
- The model's reply is restored before it is shown.
- Conversation summaries, memories, knowledge-scan notes and failed-turn errors
  are restored before they are stored or shown.

One mapping covers one agent turn — or every turn of one `/goal` run, with its
goal checks. It is never shared between sessions and is discarded when the turn
or the `/goal` run ends, so the same pod can be `<POD_0>` in one turn and
`<POD_1>` in the next.

## Plain names

A namespace, cluster or service name that is an ordinary word (`payments`) or
has no letters (`503`) is masked where a label marks it. Within a turn it is also
replaced in unlabelled forms — a table cell, a path, a command flag — only:

- from the request in which it appears with `:` or `=` after its label
  (`namespace: payments`) or as a structured field (`"namespace": "payments"`);
- from the request after the agent passes it to a tool.

A label followed only by a space does not start this. To replace a plain name in
every form from the first request, name it in `OPENSRE_MASK_EXTRA_REGEX`, for
example `'{"ns_name": "\\\\bpayments\\\\b"}'`.

## Environment variables

| Variable | Default | Description |
| --- | --- | --- |
| `OPENSRE_MASK_ENABLED` | `false` | Master switch. Set to `true` / `1` / `yes` / `on` to activate masking. |
| `OPENSRE_MASK_KINDS` | `pod,namespace,cluster,hostname,account_id,ip_address,email,service_name` | Comma-separated list of identifier kinds to mask, matched without regard to case. Empty value masks every kind. |
| `OPENSRE_MASK_EXTRA_REGEX` | *(empty)* | Optional JSON object mapping a label → regex for custom identifiers. Example: `'{"jira_key": "\\\\b[A-Z]+-\\\\d+\\\\b"}'`. Group 1 of the regex, if present, defines the span to mask. |

While masking is on, an invalid setting stops the request and the turn ends with
an error naming the setting: an `OPENSRE_MASK_EXTRA_REGEX` that is not a JSON
object of valid regexes, or an `OPENSRE_MASK_KINDS` entry that names no kind —
whatever the other entries name. Fix the setting and send the message again.

An `OPENSRE_MASK_EXTRA_REGEX` pattern runs over all the masked content of every
request, tool output included (up to 1 MiB from one command), so a slow pattern
slows every turn. A pattern that can start anywhere inside a long run of the
characters it repeats is retried from each of those starts:
`\b[a-z0-9-]+\.corp\.example\.com\b` takes seconds on 64 KB of `a-a-a-…` and
minutes on 1 MiB. Let it start only where such a run starts —
`(?<![a-z0-9-])[a-z0-9-]+\.corp\.example\.com\b` finds those names in
milliseconds.

<Note>
An `OPENSRE_MASK_KINDS` list written in upper case (`POD,NAMESPACE`) used to
mask every kind. It now masks only the kinds it names.
</Note>

## Built-in identifier kinds

| Kind | Example input | Example placeholder |
| --- | --- | --- |
| `pod` | `etl-worker-7d9f8b-xkp2q` | `<POD_0>` |
| `namespace` | `kube_namespace:tracer-test` | `kube_namespace:<NAMESPACE_0>` |
| `cluster` | `eks_cluster:prod-us-east-1` | `eks_cluster:<CLUSTER_0>` |
| `service_name` | `service:checkout-api` | `service:<SERVICE_NAME_0>` |
| `hostname` | `kind-control-plane`, `ip-10-0-1-23.ec2.internal` | `<HOSTNAME_0>` |
| `account_id` | `123456789012` | `<ACCOUNT_ID_0>` |
| `ip_address` | `192.168.1.50` | `<IP_ADDRESS_0>` |
| `email` | `alice@example.com` | `<EMAIL_0>` |

## What is not masked

- Image bytes sent to a vision model. The text description it returns is masked
  like any other content.
- Files a CLI provider's binary reads on its own from its working directory.
- Prompt-log events.
- The coding-agent tasks of `resolve_merge_conflicts` and `code_implement`. The
  `fix_github_pr_ci`, `fix_github_security_alert` and `fix_sentry_issue` tasks
  are masked when they are built.

## Round-trip guarantee

For the built-in detectors and extra regex patterns, `mask → unmask` restores
the original text byte-for-byte.

## Relationship to guardrails

Masking is complementary to the one-way `GuardrailEvaluator`. Guardrails handle
hard-block rules (credit cards, API keys) and replace matches with `[REDACTED]`
irreversibly. Masking handles infrastructure identifiers reversibly so they can
be restored for tools and for what you see.

Guardrails apply at the LLM client layer to the already masked request, so a
guardrail rule never sees a value masking replaced. To keep a kind under a
one-way guardrail rule instead, leave it out of `OPENSRE_MASK_KINDS`.

## Example

```bash
export OPENSRE_MASK_ENABLED=true
export OPENSRE_MASK_KINDS=pod,namespace,cluster,hostname
opensre ask "why is the checkout pod crash-looping?"
```

The LLM sees placeholders; the final answer shows the original pod, namespace
and cluster names.
